Have Claude Code log the session you just finished

You spent the afternoon in Claude Code on a client's repo. You never started a timer, and now you're rebuilding the afternoon from memory. Claude Code already knows when you started and when you stopped. With Freelance Tracker's MCP server, it can log that time to Toggl for you, and you check every entry before it's written.

~5 min setup Claude Code Toggl 1 Toggl call per entry

Where you'll end up

At the end of a session, one sentence turns into a Toggl entry:

claude · ~/dev/acme-storefront

/log-session Acme Corp

This session runs from 1:40pm to 5:25pm, with a 45-minute gap after 3:10pm. That makes two entries. Here's the first:

freelance-tracker · log_time (preview)

Log Tue Oct 20 1:40pm–3:10pm (1.50h) to Acme Corp — checkout flow refactor
Nothing has been written yet.

Log it?

yes

freelance-tracker · log_time (confirm)

Logged. Second entry: Tue Oct 20 3:55pm–5:25pm (1.50h), “cart tests and PR review”. Log it?

The 💰 total in your menu bar updates as soon as each entry lands. You don't need to press Refresh.

01 Turn on agent access

Open the dashboard, then ··· → Settings → Integrations → Agents (MCP), and tick two boxes:

  • Enable MCP server. This lets agents read your hours, pacing and projection. Reads come from the app's cache and never call Toggl.
  • Allow agents to log and edit time. This is the switch for this guide. It's off by default.

Leave Anonymize client names off. With it on, writes are refused: an agent that only sees “Project A” shouldn't be logging billable hours.

02 Register the server with Claude Code

Run this once. User scope makes the server available in every project, which is what you want: you'll log time from whichever repo you're working in.

claude mcp add --scope user freelance-tracker -- \
  ~/.freelance-tracker/venv/bin/python \
  ~/.freelance-tracker/mcp_server.py

Check that it connected with claude mcp list. The Settings pane also has a Test server button and a copy button with your real paths filled in, if you installed somewhere else.

03 Where the times come from

Claude Code saves every session as a transcript in ~/.claude/projects/, in a folder named after your working directory. Each message in it carries a UTC timestamp. The newest file in that folder is the session you're in.

That gives the agent everything it needs: your first message is the start, your last message is the end, and any long silence in between is a break.

45 min away
1:40pm3:103:555:25pm
Entry 11:40pm–3:10pm · 1.50h
Entry 23:55pm–5:25pm · 1.50h

The agent has to convert those UTC times to your local time, because log_time takes a local date and a 24-hour start time. The prompt below spells that out, along with how to round and where to split.

04 Ask for it

Paste this at the end of a session, with your Toggl project name in place of Acme Corp:

Log the time for this session to Acme Corp using freelance-tracker.

Get the times from this session's transcript: the newest .jsonl file in ~/.claude/projects/ for this working directory. Use the timestamps of my messages, not tool output. Convert them from UTC to my local time.

- Start at my first message and end at my last one.
- Wherever I was silent for more than 30 minutes, split into separate entries.
- Round each entry to the nearest 15 minutes.
- For the note, describe what we worked on in a few words.

Preview each entry with log_time and wait for my yes before logging it.

Change the numbers to suit how you bill. If you charge in 6-minute increments, say “round up to the next 6 minutes”.

05 Read the preview, then say yes

The first log_time call writes nothing. It checks the project name against your Toggl projects and returns a preview with the date, the time range, the hours, the project and the note. If you already logged part of that afternoon by hand, the preview flags the overlap, so you don't bill it twice.

The preview comes with a one-time token. Only when you say yes does the agent call again with it. The token:

  • works once,
  • expires after 10 minutes,
  • is tied to the exact entry you saw. A token for a 1.5-hour entry can't confirm an 8-hour one.

Two blocks mean two confirmations. Every write covers exactly one entry, so a split session asks you twice. That's deliberate: you see each entry before it lands, and an agent can't log a week in one go.

06 Make it one command (optional)

Save the prompt as a custom slash command and you'll never paste it again. Create this file:

~/.claude/commands/log-session.md

---
description: Log this session's time to Toggl via Freelance Tracker
argument-hint: <Toggl project name>
---

Log the time for this session to $ARGUMENTS using freelance-tracker.

Get the times from this session's transcript: the newest .jsonl file in ~/.claude/projects/ for this working directory. Use the timestamps of my messages, not tool output. Convert them from UTC to my local time.

- Start at my first message and end at my last one.
- Wherever I was silent for more than 30 minutes, split into separate entries.
- Round each entry to the nearest 15 minutes.
- For the note, describe what we worked on in a few words.

Preview each entry with log_time and wait for my yes before logging it.

Then end any session with /log-session Acme Corp.

What the agent can and can't do

One entry per call

No lists, no date ranges, no “log the whole week”.

Nothing without your yes

Every write is previewed first and needs its own token.

Time entries only

It can log, edit or delete one entry. It can't touch projects, rates or settings.

Recorded

Each confirmed write is 1 Toggl call, logged in ~/Library/Logs/toggl-api-audit.log. Previews are free.

Logged something wrong? Ask the agent to fix it: “that last entry should have been 2 hours” or “delete the duplicate from Tuesday”. Edits and deletes are previewed and confirmed the same way.

If something goes wrong

“Write access is off”
Tick Allow agents to log and edit time in Settings → Integrations → Agents (MCP), and Save.
“Unknown project”
The name has to match a Toggl project. The error lists the ones it knows, so the agent can usually correct itself.
“That confirmation is unknown or has expired”
More than 10 minutes passed, or the token was already used. Ask the agent to preview the entry again.
The times are off by hours
The agent skipped the UTC conversion. Tell it your time zone and ask it to redo the preview.
